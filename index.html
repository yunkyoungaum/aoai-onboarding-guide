쿼터 확인

필수

쿼터는 구독 전체가 아니라 리전 · 모델 · 배포 단위로 TPM(분당 토큰) / RPM(분당 요청)으로 할당됩니다.

  • 확인 위치: Azure AI Foundry 포털 → Quotas, 또는 Azure Portal → 구독 → Usage + quotas
  • 원하는 모델이 원하는 리전에 존재하고 TPM 여유가 있는지 확인
  • 부족하면 Quota 증설 요청 제출 (또는 계정팀 경유)
  • 대규모/일정 트래픽이면 PTU(Provisioned) 또는 Global 배포 + 다중 리전 로드밸런싱 검토
TPM은 배포에 나눠 할당되므로, 배포를 여러 개 만들면 리전 쿼터를 서로 나눠 씁니다.

모델 배포 방식 (간략)

OAI는 model 이름을 직접 쓰지만, AOAI는 모델을 배포(Deployment)로 만들고 배포 이름을 호출합니다.

  1. Foundry 포털 → Deployments → Create
  2. 모델 + 버전 선택 → 배포 유형 선택 (아래)
  3. TPM 할당 → 배포 이름 지정 → 생성
  4. 코드에서 model 자리에 배포 이름 사용 + api-version 지정

배포 유형 — Standard(단일 리전) · Global Standard(광역·저비용) · DataZone(권역 내) · Provisioned/PTU(예약 처리량).

endpoint = https://{resource}.openai.azure.com
auth     = api-key  또는  Entra ID(Managed Identity)
model    = <deployment name>   # 모델명 아님
api-version = 2024-xx-xx

네트워크 구성: Public vs Private

배포 후 리소스 접근 경로를 어떻게 열지 결정합니다. 보통 AOAI 전환의 핵심 이유가 Private(사설망) 격리입니다.

Public 배포

  • 퍼블릭 엔드포인트로 인터넷에서 접근
  • 키 또는 Entra ID 인증으로 보호
  • 방화벽 규칙으로 허용 IP/VNet 제한 가능
  • 구성 간단 · PoC/개발에 적합

Private 배포

  • Private Endpoint + VNet 통합
  • 퍼블릭 액세스 완전 차단 (Disabled)
  • Private DNS Zone로 사내망 해석
  • Managed Identity·CMK와 결합 → 프로덕션 권장

Public Network Access 설정: Enabled / Enabled with rules(IP·VNet 허용) / Disabled(Private Endpoint 전용).

Private로 완전 격리하려면 Public access를 Disabled로 두고, Private Endpoint + Private DNS Zone(privatelink.openai.azure.com)을 반드시 함께 구성해야 사내 이름 해석이 됩니다.

콘텐츠 필터링 Off (Modified Guardrails)

승인 필요

유해 콘텐츠(Hate·Sexual·Violence·Self-harm) 실시간 차단 필터를 부분/완전히 끄는 신청입니다.

  • severity 임계값 조정은 신청 없이 가능 — 완전/부분 Off는 승인 필요
  • Microsoft 계정팀 관리(managed) 고객만 신청 가능
  • 승인 후: 커스텀 필터 구성 생성 → 각 배포에 연결
Protected material(code) 필터를 끄면 Customer Copyright Commitment 커버리지에 영향 → 신중히 결정.

인증 · 보안

권장

AOAI 전환의 핵심 강점. 키 기반에서 키리스(Managed Identity)로 넘어가는 것을 권장합니다.

  • Managed Identity + RBAC — 키 대신 Cognitive Services OpenAI User / Contributor 역할 부여
  • 키를 쓴다면 Key Vault에 보관 (코드·환경변수 하드코딩 금지)
  • CMK(고객 관리 키) 암호화 필요 여부 검토
  • 저장 기능(Stored completions · Responses API data store) 사용 시 저장 위치·레지던시 인지
데이터 레지던시: Global/DataZone 배포는 처리(processing)가 광역일 수 있음. 저장(at rest)은 지정 geography 내.

안정성 · 관측성 · 비용

프로덕션

안정성 (HA)

  • 다중 리전 + 로드밸런싱 / failover
  • APIM을 AI Gateway로 — 토큰 제한·스로틀링·라우팅
  • 지연·일정 트래픽이면 PTU
  • 429: Retry-After + 지수 백오프

관측성 · 비용

  • Azure Monitor / App Insights + Diagnostic logs
  • Cost Management + 태그로 배포별 토큰 추적
  • PTU 예약으로 비용 최적화
  • 모델 버전 retirement 일정 관리
